# i18n Rollout Plan

> Spec: `docs/specs/18-i18n.md`. Convention for every task below: move hardcoded strings into `lang/en/<area>.php` + `lang/id/<area>.php` (same keys; `LangParityTest` enforces it), use `useTranslation().t()` in React and `__()` in controllers, run `sail npm run check`, `sail npm run types:check`, `phpstan`, and the area's tests.

## Done (2026-10-02)

- Infrastructure: `Locale` enum, `users.locale`, `SetLocale`, `PUT /locale`, shared `locale`/`locales`/`translations`, `t()` hook, language switcher, `lang/id` framework files.
- Pilot: users index/create/edit, appearance settings, `roles` labels.

## Remaining (suggested order)

1. **Shell:** `app-sidebar.tsx`, `nav-user`, `user-menu-content`, breadcrumbs, `settings/layout`; language switcher on guest layout.
2. **Auth & settings:** `pages/auth/*`, `settings/{profile,security,attendance}`, passkey/2FA components.
3. **Master data:** teachers, guardians, students (+ import wizard), classes, academic years, RFID cards, non-school days. Gender labels (`L`/`P`) translate at display.
4. **Attendance & excuses**, **reports** (CSV header locale), **dashboard**.
5. **Controller messages:** remaining `Inertia::flash('toast', …)` and hardcoded error strings via `rg "flash\('toast'|abort\(" app`.
6. Dates/numbers: use `Intl` with the active locale where pages format them.
7. Lint guard (optional): a test or script that fails on new JSX text literals in `resources/js/pages`.
