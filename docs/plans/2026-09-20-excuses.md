# Spec 04 — Absence Excuses (Sakit & Izin)

## Context

Implements `docs/specs/04-excuses.md` — the fourth spec in the build order (01–03 shipped). Guardians currently have no way to explain a child's absence; admins correct records by hand on the exception dashboard. This adds: guardian submits a sick/leave excuse (date range + reason + optional JPG/PNG/PDF proof) → admin approves/rejects with an optional review note → approval atomically writes `sick`/`leave` attendance across the range. Teachers see excuses for their homeroom classes read-only.

**Locked user decisions (2026-09-19):**
1. **School days only** — approval writes only days where `SchoolSettings::isSchoolDay()` is true (skips weekends + `non_school_days`; spec's "weekday" wording predates non-school days).
2. **Full excused overwrite** — an existing record in range becomes the canonical excuse row: status = sick/leave, `checked_in_at`/`checked_out_at`/`scan_method`/`override_by_user_id`/`notes` all null. The morning tap survives in append-only `scan_events`.
3. **Terminal states** — pending → approved | rejected only. Approve/reject on a resolved excuse = no-op info flash, no error. Mind-changes = guardian resubmits.

**No engine changes needed:** the excused shield (`AttendanceScanService.php:108-111`) already keys on `status in [sick, leave]`, and the sweep skips students with existing records — future approvals pre-block it naturally. Both are regression-tested, not modified.

**Not in scope:** teacher approval, multi-child submissions, PDF generation, guardian edit/cancel of pending excuses, spec-05 notifications.

### 4. FormRequests — `app/Http/Requests/Excuses/`
**`StoreExcuseRequest`** — `authorize()`: Parent role && `guardian !== null` (UpdateGuardianContactRequest precedent). Rules: `student_id` required/integer/`exists:students,id`; `type` `Rule::enum(ExcuseType::class)`; `start_date`/`end_date` required `date_format:Y-m-d`, end `after_or_equal:start_date`; `reason` required string max:2000; `attachment` nullable `file` `mimes:`+config `max:`+config. `after()` closures (StoreUserRequest style):
1. **Pivot link** — `$guardian->students()->whereKey($studentId)->doesntExist()` → error on `student_id`
2. **Inclusive overlap** — `Excuse::where('student_id', …)->whereIn('status', [pending, approved])->where('start_date', '<=', $end)->where('end_date', '>=', $start)->exists()` → error on `start_date`. Rejected doesn't block; adjacent ranges allowed.

**`ReviewExcuseRequest`** — `authorize()`: Admin only; `review_note` nullable string max:1000.

### 5. Approval service — `app/Services/Attendance/ExcuseApprovalService.php`
`__construct(private readonly SchoolSettings $settings)`. `approve(Excuse $excuse, User $reviewer, ?string $reviewNote): bool` / `reject(...): bool` — bool = whether the pending→resolved transition ran (drives no-op flash).

- **reject()**: conditional update `->whereKey(…)->where('status', Pending->value)->update([…]) === 1`; no attendance writes.
- **approve()**: `DB::transaction`: re-fetch `lockForUpdate()` (pgsql-real, sqlite no-op); status !== Pending → `return false`. Stamp excuse. Map type→`AttendanceStatus`. Loop `start_date->toDateString()`…`end_date->toDateString()` by day — **Y-m-d strings only** (date-cast Carbons carry UTC midnight; negative-offset school tz shifts the day — known spec-03 trap):
```php
if (! $this->settings->isSchoolDay($day)) { continue; }
$values = ['status' => $status, 'checked_in_at' => null, 'checked_out_at' => null,
    'scan_method' => null, 'override_by_user_id' => null, 'notes' => null];
try {
    Attendance::query()->updateOrCreate(['student_id' => $studentId, 'date' => $day], $values);
} catch (UniqueConstraintViolationException) {
    // Scanner/sweep won the (student_id, date) insert — re-fetch and
    // overwrite (same create-once rule as scan service / bulkPresent).
    Attendance::query()->where('student_id', $studentId)->whereDate('date', $day)
        ->firstOrFail()->update($values);
}
```
